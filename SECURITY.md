# Security Policy

## Reporting

Please do not publish credentials, API keys, personal data, or exploit details in public Issues.

For a potential vulnerability:

1. Contact the repository owner privately through the GitHub profile.
2. Describe the affected component and expected impact.
3. Include safe reproduction steps that do not target third-party systems.
4. Allow time for validation and remediation before public disclosure.

## Scope

Useful reports include:

- dependency or supply-chain vulnerabilities,
- unsafe handling of credentials or local storage,
- code paths that could expose sensitive data,
- build or deployment integrity issues,
- security-sensitive regressions in the simulator.

## Safety

This repository is an educational simulator. Security testing must stay within systems and data you are authorized to use.
